# 期刊線上編目系統 PHP 後端

依 `base.js` 呼叫的 API 寫成，需要 PHP 7.4+，不需資料庫（資料存成 JSON 檔）。
部署：整個資料夾放到 `/libbook/journal/`，`data/` 要讓 PHP 可寫入。

| 端點 | 參數 | 回傳 |
|---|---|---|
| `givePageNum.php` | `book` | 影像編號陣列 `["001","002"]` |
| `giveimg.php` | `b`、`p` | 影像檔（找不到則用 `img/show.jpg`） |
| `givePageno.php` | `book`、`page`（或 `all`） | 印刷頁碼；`all` 為 `{影像編號:[影像編號,期刊,序號,頁碼]}`；沒有則空字串 |
| `giveData.php` | `book` | 篇目物件；沒有則 `{}` |
| `saveIndex.php` | `book`、`tmpData` | `ok`；覆蓋前會備份到 `data/<期刊>/history/` |
| `saveMeta.php` | `book` + `action=get`，或 `book` + `meta` | 編目 JSON／`ok` |
| `savePageno.php` | `book` + `page`、`pageno`，或 `book` + `data` | `ok`（修改頁碼頁面用，原系統不在 base.js 內） |

## 儲存位置
- 影像：`img/<期刊名>/<影像編號>.jpg`（副檔名可為 jpg/png/gif/webp）
- 資料：`data/<網址編碼的期刊名>/index.json`、`meta.json`、`pageno.json`

## 和現有系統不同、需要注意的地方
- 回應一律 `text/plain`，因為前端會再 `JSON.parse(data)`，用 `application/json` 會被 jQuery 先解析而出錯。
- 沒有篇目時 `giveData.php` 回 `{}` 而非空字串（避免前端換期後殘留舊資料、翻頁事件沒綁定）。
- 伺服器端把文字中的 `<` `>` 換成全形，擋掉前端 `textOnly()` 後直接插入 HTML 的 XSS。
- `pid` 照前端送來的值存（頂層為 `start`）；前端畫樹是從 `'0'` 開始，兩者要先對齊。
- 印刷頁碼的欄位順序、影像實際存放位置、期刊清單來源，都是依推測設計，接正式系統時請對照修改 `config.php` 與 `givePageno.php`。

## 本機開啟
1. 安裝 PHP 8（或 XAMPP）。
2. 雙擊 `start.bat`，會開啟 http://localhost:8080/index.php。
3. 新增期刊：在 `img/<期刊名>/` 放 `001.jpg`、`002.jpg`…，重新整理頁面即出現在下拉選單。`img/示範期刊 v.1 n.1/` 是示範資料，可刪除。
4. 主介面是「期刊編目工作台」（`index.php` + `app.js`，沿用原型的版面與操作，資料改存伺服器）。字型從 Google Fonts 載入，沒有網路時會改用系統字型。`classic.php` 是依原系統 base.js 重建的舊版介面（需要網路載入 jQuery）。`page_work/` 是修改頁碼的獨立頁面。

## AI 辨識（Gemini）
- 金鑰放在 `config.local.php`（`define('GEMINI_API_KEY', '...')`），模型預設 `gemini-3.5-flash`，可在 `config.php` 以 `GEMINI_MODEL` 覆寫。
- 「分析本頁」：辨識當前影像的篇目，預填表單。「分析目錄」：辨識目錄頁，產生整期篇目草稿，核對後才加入。
- 影像會被送到 Google；免費版的內容可能被用於改進模型，請先確認機構規定。
- `php/` 內附的 PHP 已啟用 curl 等擴充，並以 `php/cacert.pem`（匯出自 Windows 信任憑證）驗證 HTTPS。

## 逐頁核對（主畫面）
- 「分析整期」：每 4 頁合成一次請求送給 Gemini（免費額度限制的是「請求次數」，23 頁約 6 次請求），同時處理 2 組。結果存進 `data/<期刊>/pagerec.json`，中途停止或額度用完可按「繼續分析」。
- 每頁一筆紀錄；AI 在某頁找不到標題，該頁「沿用前頁」。人工逐頁確認（Enter），狀態：已確認／待檢查／沿用前頁／缺題名／未分析。
- 「套用到篇目目錄」：把逐頁資料合併成篇目（連續沿用、或同題名同作者的頁併成一筆起訖範圍），會取代目前的篇目目錄。
- 模型依 `GEMINI_MODELS` 順序嘗試，主模型的免費額度用完（429）時自動改用下一個；備援模型的辨識品質可能較差。
- 設計草稿：`design/mockups.html`。

## 頁碼（印在書上的頁碼）
- 每頁有「頁碼」欄位（清單每列、編輯區都有），一律是阿拉伯數字；輸入「二十一」「廿三」「iv」會自動換成 21、23、4。沒有頁碼就留空，不計入頁數。
- 分析整期時 AI 順便辨識頁碼，只填空白的頁，不會蓋掉已有的；AI 填的會標「AI 辨識，請核對」。
- 資料和「編輯頁碼」頁面是同一份（`data/<期刊>/pageno.json`）。
- 備援模型 `gemini-3.5-flash-lite` 辨識的頁碼常是推算的（實測錯誤），程式不採用它的頁碼；`gemini-3-flash-preview` 實測正確，已排在 lite 前面。

## AI 設定（每位使用者自己的金鑰）
- 右上角「AI 設定」可輸入自己的 Gemini API 金鑰；「測試並儲存」會先向 Google 驗證（只查詢模型清單，不消耗辨識額度）。
- 金鑰只存在該瀏覽器的 localStorage；辨識時隨請求（`api_key`）送到 `analyze.php` 轉給 Google，不會寫入伺服器檔案。沒有輸入時才使用伺服器 `config.local.php` 的預設金鑰。
- 每把金鑰的免費額度各自計算，多人使用時各用各的，不會互相擠掉額度。非本機使用請改用 https，避免金鑰在網路上明文傳送。

## 頁碼不連續檢查
- AI 填的、尚未確認的頁碼，若和前面有數字頁碼的頁不連續（頁碼差不等於頁數差，空白頁也算一頁），清單會標「⚠ 不連續」，上方有「頁碼不連續」篩選。
- 編輯區可一鍵「改成 N，並一起修正後面連續的 M 頁」，或按「沒問題」（書本分章重新編號時）。

## 從 GitHub 取得後怎麼用
儲存庫只包含程式，不含下列檔案，需自行準備：
- `php/`：Windows 可攜式 PHP（8.x，NTS x64），從 https://windows.php.net/download 下載解壓到 `php/`，並啟用 curl、openssl、gd、mbstring、fileinfo 擴充（複製 `php.ini-development` 為 `php.ini` 後取消註解）；也可以改用系統安裝的 PHP 或 XAMPP，`start.bat` 會自動尋找。
- `img/<期刊名>/`：掃描影像（`001.jpg`…）。
- `config.local.php`：複製 `config.local.example.php`，填入 Gemini 金鑰（或讓使用者在網頁「AI 設定」自己輸入）。
- `data/` 會在使用時自動建立編目資料。
## 線裝書（頁碼在中縫）
- 在上方「資料類型」下拉選單選「線裝書」（選項：一般類型、期刊、線裝書、公報、報紙；存成這一期的 meta）。選了之後，分析時 AI 以書葉中縫（版心）上的頁（葉）次數字為主，並用較高解析度送圖。
- 任何一頁填好（或改好）數字頁碼、按「確認」後，同一篇目後面「沿用前頁」的頁會自動更新成 N+1、N+2……（一張影像算一頁）。一般書遇到下一個新標題就停止（下一篇的首頁不自動接續）；線裝書同一冊葉次連續，會跨過篇目繼續接續。遇到尚未分析的頁、或和預期頁碼不吻合的已確認頁（可能是重新編號）就停止。
- 已有頁碼的頁：只要還沒確認就會被更新；已確認的頁不動（但後面仍照順序編號）。自動填的頁碼標「自動接續」，提示上有「復原」可一鍵還原。

## AI 頁碼建議
- 重新分析時，如果某頁已經有頁碼、AI 這次辨識到不同的頁碼（且該頁還沒確認），不會直接覆蓋，而是列為「AI 建議」：清單該頁顯示「AI 建議 N」，編輯區可「改成 N」或「保留原值」，上方也有「採用全部 AI 頁碼建議」（可復原）與「AI 頁碼建議」篩選。
- 空白的頁仍會直接填入 AI 辨識的頁碼。已確認的頁不受影響。
- 備援模型 lite 的頁碼：一般書不採用（常是推算的）；線裝書模式（讀中縫）實測可用，會採用。

## 還原本期到最初狀態
- 「匯出與還原」視窗最上方的按鈕，一鍵把這一期回到**第一次用 AI 分析之前**的樣子：逐頁核對資料變回「未分析」、AI 填的頁碼與篇目目錄一併回到當時；載體編目（資料類型等）不受影響。
- 第一次 AI 分析時（`analyze.php`，不含框選辨識）自動記下最初狀態，存在 `data/<期>/initial/`（`restoreInitial.php` 負責還原）。
- 還原前會先把目前狀態備份到 `data/<期>/before-restore/<時間>/`，最多保留 5 份，按錯了可以手動複製回來。
- 這個功能加入**之前**就已分析過的期別沒有真正的最初狀態，改用推測：逐頁核對資料清空、逐頁核對裡標為「AI 辨識／自動接續」的頁碼移除、篇目回到 `history/` 裡最早的備份（沒有備份就維持現況）。

## 評測腳本（eval/）
- `node eval/evaluate.js --gold <標準答案.csv>`：用既有的編目紀錄當考卷，量測 AI 的頁碼、題名、作者、專欄、角色、廣告的準確率（含編造率、題名錯字率、各輪穩定度），並產生報告與錯誤清單。
- 比對前 AI 輸出和標準答案都先經過同一套正規化（全形半形、標點、異體字、頁碼取較小者）。
- 用法、標準答案格式、評測流程建議見 `eval/README.md`；自我檢查：`node eval/test.js`。
- 標準答案、快取與報告放在 `eval/gold/`、`eval/cache/`、`eval/out/`，已加入 `.gitignore`。
